# aqsclient

An R client generated by specmill from the EPA Air Quality System schema.
Includes all 79 schema operations, generated help pages, offline request tests,
and the schema and configuration needed to regenerate the client.

## Build and install

Install R, then open a terminal in the `aqsclient` folder and run:

```sh
Rscript init.R
```

The script reports four steps as it runs:

1. Check dependencies and install any missing packages from CRAN.
2. Build the package archive in `build/`.
3. Install the client in this folder's `library/` directory.
4. Run offline tests to check request construction.

Setup needs internet access only if dependencies are missing. It does not call
AQS or require API credentials. Specmill is only needed for regeneration.
Tested with R 4.5.0 on Linux.

After setup, open R in this folder and run:

```r
.libPaths(c('library', .libPaths()))
library(aqsclient)
```

For a standard installation into your usual R library, install `httr2`,
`jsonlite`, and `curl`, then run `R CMD INSTALL .` from this folder.

## Use your own AQS account

Copy `.Renviron.example` to `.Renviron`, fill in your email and key, and load it:

```r
library(aqsclient)
readRenviron('.Renviron')
meta_data_is_available()
list_states(email = Sys.getenv('AQS_EMAIL'))
sample_data_by_state(
  email = Sys.getenv('AQS_EMAIL'),
  param = '88101', bdate = 20180303L, edate = 20180303L, state = '16'
)
```

The client reads `AQS_KEY` from the process environment on every authenticated
request. R loads `.Renviron` at startup; after editing it, restart R or call
`readRenviron('.Renviron')` explicitly. No `set_api_token()` call is needed.
Email remains an explicit argument. Existing callers must remove `key = ...`;
76 generated wrappers now get their key exclusively from `AQS_KEY`.

`.Renviron` is excluded from Git and package builds. Environment lookup does not
redact query credentials: dry-run request objects and httr2 request printing can
expose the key. Treat request objects, verbose traces, hooks, and recordings as
sensitive. No automatic `.env` loading is performed.

Dates are YYYYMMDD integers. State, county and site codes are strings retaining
leading zeroes.

## Known live API differences

The following differences were observed in September 2026 and have not been
retested against the live API during this rebuild:

- `transactions_sample_by_state()`, `_by_county()`, `_by_site()`, and `_by_ma()`
  require `units = NULL`. The live API rejects the schema default `standard`.
- `transactions_sample_by_poc()` returns HTTP 422: no matching service exists.
- Use `meta_data_is_available()` for health checks. `service_available()` returns
  an untyped body containing HTTP headers rather than the declared JSON.
- `signup()` creates an account or resets the account key and sends email.

Example transaction request:

```r
transactions_sample_by_state(
  email = Sys.getenv('AQS_EMAIL'), param = '88101',
  bdate = 20180301L, edate = 20180301L, state = '16', units = NULL
)
```

## Schema and regeneration

`schema/openapi.json` is the unmodified EPA download. [Source and checksum](schema/SOURCE.md).
The `apis/` YAML files give each method/path a distinct R name, resolving the
duplicate `qaAnnualPerformanceEvaluationsBySite` operationId.

Only regeneration requires specmill. This client was regenerated with specmill
0.1.60 at the source revision below:

```r
# Maintainer setup; not needed by package users.
install.packages('remotes')
remotes::install_github(
  'seanthimons/specmill@1c1553b9233d874876f0f13c98ef09b191dc00e9'
)
```

Restart R after installing specmill, then run from this directory:

```r
specmill::generate_client('.', config = 'specmill.yml', mode = 'plan')
# Review the plan before applying:
specmill::generate_client('.', config = 'specmill.yml', mode = 'apply')
specmill::generate_client('.', config = 'specmill.yml', mode = 'check')
```

Keep `.specmill/` with the project: it tracks generated-file ownership and helper
provenance. The pinned revision records the generator used for this rebuild.

The reviewed service configuration excludes the redundant query `key` argument
on 76 operations. Twelve annual, daily, and sample data routes also receive an
explicit security correction because the archived schema requires query `key`
and `email` but omits the security requirement. Public status and registration
configuration are unchanged. These corrections do not establish live API behavior.
